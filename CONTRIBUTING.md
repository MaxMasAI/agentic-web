## 🌟 Code of Conduct

We are committed to providing a welcoming, inclusive, and harassment-free environment for everyone. Please be respectful, constructive, and collaborative in all discussions, issues, and pull requests.

## 🚀 Quick Start for Contributors

### 1. Fork & Clone
1. Fork the repository on GitHub: [`https://github.com/MaxMasAI/agentic-web`](https://github.com/MaxMasAI/agentic-web)
2. Clone your fork locally:
```bash
git clone https://github.com/MaxMasAI/agentic-web.git
cd agentic-web
```

### 2. Set Up Virtual Environment
```bash
# Windows
python -m venv .venv
.venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt

# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### 3. Run in Live Development Mode
Use the live auto-reload dev runner to test your changes with automatic restart on save:
```bash
# Windows 1-Click
dev.bat

# CLI Dev Runner
python dev.py
```

## 📁 Repository Guidelines & Architecture

When contributing code, please adhere to our architectural layout:

* **`system/`**: All OS-level automation, FancyZones window tiling (`system/fancyzones_manager.py`), Antigravity System Cursor (`system/system_cursor.py`), Security Guard, Sandbox, and Issue Reporter (`system/issue_reporter.py`). *Do not create duplicate system modules in `browser/` or `services/`.*
* **`gui/`**: PySide6 desktop interface components, theme styling (`APP_QSS`), widgets, and full-width settings pages.
* **`core/`**: Multi-model Leader-Worker orchestration loops, debate protocols, and agent lists.
* **`services/`**: Resilient API Gateway (`services/resilient_gateway.py`), GitHub service, and configuration managers.
* **`tests/`**: Unit test suites. Every new service or fix must include tests in `tests/test_<feature>.py`.

---

## 🧪 Running Tests

Before submitting a Pull Request, make sure all test suites pass:

```bash
# Run all system and core tests
python -m unittest tests/test_security_guard.py tests/test_resilient_gateway.py tests/test_state_store.py tests/test_system_package.py tests/test_fancyzones_manager.py tests/test_issue_reporter.py

# Run complete discover suite
python -m unittest discover tests
```

## 🌿 Branching Strategy & Commit Messages

* **Branch Naming:**
  * `feat/your-feature-name` (New capability or agent skill)
  * `fix/bug-description` (Bug fix or patch)
  * `docs/improvement` (Documentation or guide update)
  * `refactor/component` (Code quality or architecture improvements)

* **Commit Format:**
  * Use clear, imperative messages:
    * `feat(fancyzones): add multi-monitor priority grid support`
    * `fix(gateway): resolve token bucket rate-limit edge case`
    * `docs(readme): add contributing guide and badge tags`

---

## 📤 Submitting a Pull Request (PR)

1. Push your branch to your GitHub fork:
   ```bash
   git push origin feat/your-feature-name
   ```
2. Open a Pull Request against `MaxMasAI/agentic-web` (`main` branch).
3. Fill out the PR description template:
   * **Summary of Changes**: What does this PR do?
   * **Motivation / Linked Issues**: Mention `Closes #<issue_number>` or `Fixes #<issue_number>`.
   * **Testing Performed**: Detail unit tests or manual verification steps.
4. The maintainers will review your PR and provide constructive feedback!

---

## 🐞 Autonomous Issue Reporting

If you encounter a runtime exception or crash while developing, the application automatically logs and offers to file a structured report directly on [`MaxMasAI/agentic-web/issues`](https://github.com/MaxMasAI/agentic-web/issues) via `system/issue_reporter.py`.
